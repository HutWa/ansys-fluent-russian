# Автоматическая визуальная проверка Fluent 2026 R1

## Назначение

`reviews/v2026R1/automation/home-navigation.jou` — кандидат Fluent GUI journal: он задуман для выбора страниц `General`, `Materials`, `Graphics` и `Surfaces`, с паузами для захвата. Скрипт не читает и не сохраняет case, не изменяет настройки и не запускает расчёт.

Перед запуском journal проверяется статически: `python scripts/check_visual_journal.py reviews/v2026R1/automation/home-navigation.jou`. Разрешены только выбор узла дерева и паузы, поэтому в сценарий не может попасть команда изменения модели или расчёта.
`launch_fluent.py --journal` выполняет ту же проверку и откажется запускать journal с другой командой.

Вместе с `scripts/capture_fluent_window.py` это убирает ручные снимки и переходы между этими страницами. Журнал использует внутренние английские пути Fluent; на кадрах оцениваются именно отображаемые русские подписи. В v261 путь дерева из первого кандидата не найден, поэтому его нельзя считать рабочим до исправления.

## Запуск

```powershell
python scripts/launch_fluent.py --fluent-root "D:\games\ANSYS Inc\ANSYS Student\v261\fluent" `
  --capture-output build/visual-qa-journal `
  --journal reviews/v2026R1/automation/home-navigation.jou -- 3d -t1
```

После завершения journal Fluent остаётся открытым, а кадры лежат в `build/visual-qa-journal`. Наблюдатель завершится после закрытия Fluent. Кадры и манифест исключены из Git.
Если кадры не появились, точная причина записывается в `build/visual-qa-journal/watcher.log`.

## Интерактивная задача Windows

Для запуска из сессии рабочего стола, а не из изолированной среды агента, `scripts/run_visual_qa_task.cmd` служит короткой точкой входа задачи Планировщика Windows и сохраняет результаты в `build/visual-qa-task-physics-clean`. После старта Fluent `scripts/navigate_fluent_visual_qa.py` ожидает именно готовое окно `Fluent@Home`, а режим `physics-ribbon` открывает только ленту «Физика». Режим `home` двойным кликом выбирает уже отображённые строки дерева `Materials`, `Graphics` и `Surfaces`, затем посылает `Enter` для открытия выбранной страницы. Заставка и окно ошибки лицензии исключены. Координаты, число кликов и клавиша записываются в `navigation-trace.json`; скрипт не посылает команд модели, case, сетке, решателю или сохранению.

Вывод интерактивной задачи перенаправлен в `task-run.log` в том же каталоге. В нём также отмечены начало и код возврата launcher и навигатора. Это позволяет отличать отсутствие окна, ошибку запуска и ошибку навигации без ручного просмотра консоли Планировщика Windows.

Если Планировщик Windows не продолжает batch после создания Fluent, `scripts/run_physics_navigation_task.cmd` выполняется отдельной интерактивной задачей после появления окна. Он не запускает Fluent и не выполняет действий в модели: только выбирает ленту «Физика» и ведёт `navigation-run.log`.

`scripts/capture_physics_ribbon_task.cmd` — независимый одноразовый захват уже видимого окна после навигации. Он запускает только `capture_fluent_window.py`, записывает `physics-capture.log` и не передаёт Fluent никаких действий.

Для подготовки чтения существующего case `open_fluent_case_dialog.py` посылает только `Ctrl+O` уже готовому Home-сеансу. Он не вводит путь, не читает и не сохраняет case. `list_visible_windows_task.cmd` записывает заголовки видимых окон, чтобы подтверждать появление диалога до любого следующего действия.

Для приоритетного `Multiphase Model` пара `run_multiphase_navigation_task.cmd` и `capture_multiphase_task.cmd` использует маршрут «Модели → Многофазная модель» в дереве загруженного case. Он только раскрывает ветку и открывает диалог конфигурации, не выбирает модель и не нажимает «Применить». Захват ищет именно окно `Multiphase`, а не фоновое окно Fluent; журнал и кадр сохраняются отдельно в `build/visual-qa-task-multiphase`.

## UI Automation для страниц дерева

Координаты дерева меняются при другой высоте окна и при раскрытии веток. Для таких страниц `scripts/navigate_fluent_uia.py` сначала находит элемент по опубликованному Fluent UIA-имени, прокручивает только панель дерева и двойным щелчком открывает элемент из жёсткого белого списка `SAFE_TARGETS`. Текущий маршрут `run-calculation` открывает только «Запуск расчёта»; он не посылает `Рассчитать`, инициализацию, сохранение, команды solver или изменения case. Нужна локальная библиотека `pywinauto`; результат по-прежнему считается проверенным лишь после отдельного фактического кадра из `capture_fluent_window.py`.

## Изолированный case для приоритетных окон

`launch_readonly_case.py` сначала создаёт побитово проверенную копию source case, затем запускает Fluent с bootstrap-journal, содержащим единственную команду `/file/read-case` для этой копии. Он не является GUI-journal: GUI-навигация остаётся отдельной и не может менять данные. Metadata фиксирует два SHA-256, путь к копии и точную команду запуска. `run_readonly_bioreactor_task.cmd` предназначен только для найденного тестового `bioreactor_2026R1_test_setup.cas.h5`; оригинальный файл не открывается Fluent и не изменяется. Для v261 временный каталог задан ASCII-путём `C:\Users\lol\Documents\FluentVisualQA\bioreactor`, поскольку TUI-journal не читает путь с русскими символами.

12 сентября загрузка изолированной копии подтверждена кадром с заголовком `bioreactor_2026R1_test_setup` и SST k-ω, а ветка «Модели» раскрыта на фактическом case. В `models-tree` зафиксированы только увиденные русские и английские подписи. Попытки открыть `Multiphase Model` из ленты и дерева не дали модального кадра, поэтому этот диалог не обновлён и не засчитан для beta-гейта.

Тем же изолированным проходом фактически открыта страница «Материалы»: русские заголовки подтверждены кадром, а `Fluid` и `Solid` зафиксированы как оставшиеся английские категории. Диалог редактирования материала не открывался, поэтому его состояние не экстраполируется из страницы списка.

`Solution Methods` также открыт по ветке «Решение → Методы». Все структурные подписи на кадре русские; значения схем (`Coupled`, `Second Order`, `Global Time Step`) сохранены как названия численных методов. Запись `solution-methods` подтверждена на полном пакете.

`Solution Controls` открыт стандартной навигацией `Методы → Down → Enter`; фактический кадр подтверждает русские заголовки, поля и кнопки. Запись `solution-controls` подтверждена на полном пакете.

Это временно более устойчиво, чем journal: координаты привязаны к размерам окна и должны подтверждаться кадрами на каждом обновлении Fluent. Если окно, масштаб интерфейса или порядок дерева изменился, проход отмечается как сбой автоматизации, а не как пройденная проверка.

## Фактический прогон 2026-09-11

Интерактивная задача `Codex Fluent Visual QA` выполнила чистый запуск полного пакета `beta-1-27104-visual-qa`. Артефакты локально сохранены в `build/visual-qa-task-open`: `navigation-trace.json` фиксирует три двойных клика, а `capture-manifest.json` — кадры.

- Начальная лента и страница «Общие» отображены на русском (кроме динамического `User Window 1`).
- Страница «Графика и анимация» действительно открыта; её заголовки переведены, но пункты типов и `Unavailable` ещё английские. Поэтому `graphics` остаётся `partial`.
- «Материалы» и «Поверхности» были выделены в дереве, но в пустой домашней сессии собственные страницы не открылись. Эти окна не были зачтены как проверенные.

12 сентября отдельные интерактивные задачи успешно выполнили цепочку «Home → Физика → захват»: `navigation-run.log` содержит фактический клик, `physics-capture.log` — успешный захват, а кадр подтверждает русские группы и команды ленты «Физика». Он добавлен как `physics-ribbon: partial`, поскольку динамический `User Window 1` остаётся английским.

Ранее найденный journal остановлен: его внутренний идентификатор дерева не существует в v261. Результаты выше получены из чистого координатного прогона, а не из этого journal.

## Ограничение и развитие

GUI-journal должен проверяться на каждой версии Fluent: внутренние пути элементов не являются публичным API. Если страница не открылась, это фиксируется как ошибка автоматизации, а не как результат визуальной проверки. После фактического подтверждения путей сценарий расширяется на остальные приоритетные окна beta.1.

## Прямой проход через Computer Use — 2026-09-22

Агенту доступен прямой интерактивный доступ к окну Fluent через Computer Use. Это снимает прежнюю зависимость от ручной отправки скриншотов и обходит сбой захвата окна из изолированного терминала. Для данного прохода Fluent запущен с `lang=ru`, а в Launcher через меню `Read` выбрана **проверенная побитовая копия** `bioreactor_2026R1_test_setup.cas.h5` в `C:\Users\lol\Documents\FluentVisualQA\bioreactor`; исходный case не открывался. В заголовке рабочего окна подтверждены имя case и SST k-ω. Навигация выполнялась только по ленте, дереву страниц и открывающимся диалогам; настройки моделей, сетка, расчёт и сохранение не затрагивались. Диалоги закрывались без применения изменений.

Повторяемый безопасный порядок: найти именно окно `Fluent@Home` (не Launcher и не другое приложение), после каждого действия получить новый кадр, открыть страницу двойным щелчком по узлу дерева либо открыть модальное окно через ленту, сохранить кадр из состояния окна и записать его SHA-256. Если окно не появилось или кадр относится к другому приложению, результат не засчитывать. Имена зон и материалов в кадре не считать строками интерфейса. При другом разрешении координаты меняются, поэтому маршрут определяют по видимым элементам, а не по фиксированным числам.

Фактически сохранены восемь кадров в исключённом из Git каталоге `build/visual-qa-20260922`: `boundary-conditions`, `mesh-interfaces`, `dynamic-mesh`, `surfaces`, `multiphase-model`, `energy-model`, `reports`, `plots`. Для каждого файла в `reviews/v2026R1/windows.yml` записаны относительный локальный путь и SHA-256. Это локальное доказательство, а не часть распространяемого пакета: снимки содержат название пользовательского case и не публикуются. Проверить наличие, формат и хеши всех локальных доказательств можно командой `python scripts/check_visual_review.py --verify-evidence`; обычная проверка метаданных не требует наличия игнорируемых файлов на CI.

Вывод прохода: «Энергия» переведена в видимом выключенном состоянии; остальные семь областей имеют подтверждённые дефекты или неполный охват. Особенно заметны внутренние пути вместо коротких подписей, английские типы отчётов и графиков, английские категории поверхностей и опция `Eulerian` с полным путём. Текущий пакет нельзя объявлять beta.1 только на основании того, что окна открылись. Для него `beta_blocker: true` в QA-журнале заставляет beta-гейт завершаться ошибкой до исправления и повторного осмотра.

Для 22 точно сопоставленных строк подготовлен отдельный batch `translations/v2026R1/batches/visual-qa-20260922-short-labels.json`: короткие подписи для поверхностей, многофазной модели, граничных условий и динамической сетки. Это описание первого прохода; дальнейший результат установки и повторной проверки приведён ниже.

## Повторный проход после установки исправлений — 2026-09-22

После закрытия Fluent полный пакет `beta-1-27104-qa-fix-20260922` из 553 модулей установлен с отдельной резервной копией. Хеши всех 553 установленных файлов совпали с манифестом. В Launcher подтверждено `lang=ru`. На побитовой копии case открыты все 16 текущих областей Tier 1 и несколько областей Tier 2. Последние два кадра — дерево моделей и условия ячеечной зоны — сохранены 24 сентября в `build/visual-qa-20260924-tier1`; остальные кадры находятся в `build/visual-qa-20260922-qa-fix`. Пути и SHA-256 занесены в `reviews/v2026R1/windows.yml`. Исходный case не изменялся; настройки, расчёт и сохранение не выполнялись.

При повторном запуске в Launcher был выбран пункт `Case & Data`, хотя рядом с проверенной копией имелся только `.cas.h5`. Fluent сообщил об отсутствии `.dat.h5`, но загрузил case: имя в заголовке, зоны и модель SST подтверждены. Поэтому кадры подтверждают интерфейс и структуру case, **но не загруженные результаты расчёта**. Окна, доступные только после расчёта или включения моделей, этим проходом не проверены.

Проверка подтвердила исправление коротких подписей на страницах граничных условий и динамической сетки, варианта «Эйлерова модель» и команд менеджера поверхностей. Видимые страницы «Методы», «Управление», «Инициализация» и выключенный диалог «Энергия» получили статус `verified` в указанной области. Девять областей остаются блокерами beta.1: лента/дерево, материалы, интерфейсы сетки, динамическая сетка, запуск расчёта, графика, поверхности, отчёты и графики. Их конкретные английские пользовательские подписи записаны в QA-журнале; наличие кадра само по себе не снимает блокер. Команда `python scripts/check_beta_readiness.py --package beta-1-27104-qa-fix-20260922 --staging-dir build/beta-1-27104-qa-fix-20260922` ожидаемо завершается с ошибкой.

Прямой интерактивный проход не означает, что прежний GUI-journal стал совместим с v261. Для повторения агент должен сначала определить актуальные элементы по состоянию окна, затем сохранять кадр после каждого перехода; непоявившееся окно не засчитывается. Автоматическая классификация всех страниц без участия оператора ещё требует доработки.
