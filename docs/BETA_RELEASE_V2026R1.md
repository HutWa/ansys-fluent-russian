# План beta-релиза Fluent 2026 R1

Цель первой бета-версии — дать пользователю воспроизводимый и обратимый способ установить русификацию Fluent Student 2026 R1, при этом честно зафиксировать непроверенные окна и известные ограничения.

## Текущее состояние

- Каталог содержит 28 786 классифицированных строк: 27 104 переведены, 1 682 намеренно не переводятся.
- Полная сборка `beta-1-27104-visual-qa` содержит 553 проектных Qt-каталога `.qm` и установлена в тестовую Fluent Student 2026 R1. Проверка SHA-256 подтверждает совпадение всех 553 установленных модулей с манифестом.
- Автоматические проверки каталога, QA-метаданных, репозитория и тестов проходят. Предупреждения валидатора о формулах, сокращениях и технических обозначениях допускаются, если они не являются ошибками.
- Автоматический локальный захват подтвердил главную ленту, дерево и страницу `General`; прочие приоритетные окна ещё не проверялись на этой сборке. Наблюдения из `release-5009` являются историческими и не подтверждают качество текущей сборки.

## Что блокирует beta.1

Перед выпуском должны быть выполнены все пункты ниже.

1. Полный пакет собирается из чистого staging-каталога и проходит dry-run установки.
2. Fluent запускается с `lang=ru`; кириллица отображается без ошибок загрузки.
3. По скриншотам проверены следующие приоритетные области текущей сборки:
   - верхняя лента и дерево навигации;
   - General, Materials, Energy и Multiphase Model;
   - Boundary Conditions, Mesh Interfaces и Dynamic Mesh;
   - Solution Methods, Controls, Initialization и Run Calculation;
   - Graphics, Surfaces, Reports и Plots.
4. В этих областях нет критичных дефектов: английских пользовательских заголовков и команд, подставленных внутренних путей вместо подписи, обрезанного текста, ошибочной замены технического имени или одинакового перевода у различающихся вариантов.
5. Каждое открытое окно занесено в `reviews/v2026R1/windows.yml` с датой, пакетом, областью проверки и остаточными замечаниями. Окно получает `verified` только после фактического просмотра.
6. Установка и откат подтверждены на тестовой машине с отдельной резервной копией.

## Что не является блокером beta.1

- Непереводимые идентификаторы, формулы, обозначения моделей и пользовательские имена зон, материалов и файлов.
- Неоткрытые специализированные панели, если они явно отмечены как `unverified` или `needs_recheck` и перечислены в известных ограничениях.
- Английские названия алгоритмов, когда это общепринятое техническое имя, а не обычная подпись интерфейса.

## Порядок выпуска

1. Закрыть визуальные замечания по приоритетным окнам и повторно собрать полный пакет.
2. Запустить автоматические проверки: каталог, QA-метаданные, проверку содержимого репозитория и тесты.
   Для единого beta-гейта использовать `python scripts/check_beta_readiness.py --package <номер-пакета> --staging-dir <каталог-сборки>`.
3. Обновить README, журнал визуальной проверки и раздел известных ограничений с точным номером пакета.
4. Создать коммит и Git-тег `v2026R1-beta.1`.
5. Создать GitHub Release с кратким списком изменений, поддерживаемой версией Fluent, инструкциями установки и отката, а также известными ограничениями.

В GitHub Release публикуются исходный каталог перевода, скрипты и документация проекта. Файлы Ansys, извлечённые оригинальные ресурсы и резервные копии не публикуются.

Актуальные ограничения для текста GitHub Release поддерживаются в `KNOWN_LIMITATIONS_V2026R1.md`.

## Переход к полноценному релизу

После beta.1 расширяется визуальный охват, устраняются замечания пользователей и проводится повторная проверка изменённых окон. Полноценный `v2026R1.0` требует отсутствия критичных дефектов в ключевых рабочих сценариях, воспроизводимой установки и отката, актуальной документации и завершённого решения по лицензии проекта.
