# Сценарии visual QA Fluent 2026 R1

## Назначение

`qa_scenarios/*.yml` — единственный декларативный слой для планирования визуальной проверки. Файлы используют JSON-синтаксис, совместимый с YAML, чтобы не добавлять внешнюю библиотеку в CI. Каждый сценарий связывает окна, модули перевода, приоритет, требуемое состояние и допустимый способ навигации. Снимки остаются локальными в `build/visual-qa-*`; в Git попадают только их путь и SHA-256 из `reviews/v2026R1/windows.yml`.

Сценарии расширяют существующие `launch_readonly_case.py`, `launch_fluent.py`, UIA/coordinate-навигацию и `capture_fluent_window.py`; второй независимый QA-контур не создаётся.

## Безопасная последовательность

1. Запустить Fluent с `lang=ru` на отдельной побитовой копии case через `launch_readonly_case.py` либо открыть заранее подготовленный локальный QA-case.
2. Запустить наблюдатель захвата кадров.
3. Проверить сценарий: `python scripts/qa.py validate`.
4. Получить план без действий: `python scripts/qa.py run basic_flow --dry-run`.
5. Только при открытом изолированном case выполнить разрешённые маршруты: `python scripts/qa.py run basic_flow --execute-navigation`.
6. Проверить каждый реальный кадр, записать дату, пакет, область, SHA-256, статус и видимые замечания в `windows.yml`.
7. Запустить `python scripts/qa.py coverage --package <package>` и beta-гейт.

Команда с `--execute-navigation` не запускает Fluent и не выполняет TUI-команды. Она вызывает лишь прежние белые списки UIA/coordinate-навигации. Шаги без маршрута выводятся как задача для Computer Use/оператора: это честнее, чем хрупкий клик по неизвестному состоянию интерфейса.

После автоматического захвата его можно прикрепить без ручного расчёта хеша: `python scripts/qa.py record-capture --window <id> --image build/visual-qa-.../frame.png --package <package> --scope <scope>`. Команда ставит только `captured`; она не подменяет визуальную классификацию и не может выдать окно за проверенное.

## Уровни

- Tier 1: базовая лента, дерево, настройка, решение и постобработка. Список формируется из `basic_flow.yml` и является источником требований beta-гейта.
- Tier 2: теплообмен, турбулентность, многофазность, компоненты и динамическая сетка.
- Tier 3: редкие специализированные панели; добавляются отдельными сценариями, когда есть безопасный QA-case.

Доступность шага указывается непосредственно в сценарии: `always_accessible`, `requires_case`, `requires_model`, `requires_solver_mode`, `requires_boundary_type`, `requires_results`, `requires_operation`, `semi_automatic` или `manual_only`.

## Статусы и повторная проверка

`unverified` означает отсутствие наблюдения; `captured` — есть кадр, но он не рассмотрен; `review_required` — кадр требует решения редактора; `partial` — видимое состояние проверено не целиком; `verified` — состояние просмотрено без замечаний; `needs_recheck` — прежний результат устарел; `manual_only` — сценарий нельзя безопасно выполнить автоматически. `verified`, `captured`, `review_required` и `partial` требуют evidence с путём и SHA-256. `beta_blocker: true` применяется к фактическому критическому дефекту, а не к отсутствию кадра.

Для изменённых модулей используется: `python scripts/qa.py affected --base-ref <git-ref>`. С `--apply` подтверждённые окна, связанные с изменённым модулем, переводятся из `verified` в `needs_recheck`; остальные записи не меняются.

## Ограничения

Основной пользовательский case, модели, материалы, сетка, граничные условия, параметры решателя и результаты не изменяются. Если требуется включить модель или получить результаты, сценарий получает отдельный локальный QA-case. Такие файлы не добавляются в Git. Кадр подтверждает только видимое состояние и не переносит результат на другие вкладки или режимы.
